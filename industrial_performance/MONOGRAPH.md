# Industrial solver dispatch and the cost of exact reformulation

The previous formula consumer work established exact finite replacements for selected arithmetic curves, including affine pullbacks that retain lattice divisibility. Its solver wins were authored proof fixtures. Industrial performance requires a different test: independent source programs, all incremental queries in a declared sample, and the total cost of preprocessing and solving. This checkpoint moves that test to the complete 181-file ELSTER industrial submission rather than relying on the previously bundled 19-file subset.

The source corpus is pinned to SMT-LIB/benchmark-submission revision `bdae77b0a144895098f82b51a531bc2b566df9e6`. Acquisition checks every Git object and records a SHA-256 manifest. The corpus contains 307,442,420 bytes and, in the earlier complete query inventory, 303,946 check commands. A prefix benchmark must not be described as having executed all those queries. The earlier first-32-per-file sample selected 5,612 queries. The retained fresh report declares its own cap and exact query count. The large inputs remain outside the source archive and can be acquired automatically from the pinned repository.

Two earlier completed paired trials produced negative aggregate results. Exact positive-denominator Euclidean lifting solved 2,809 of 5,612 selected queries against 2,989 for the original, and its summed candidate wall time including preprocessing was 961.513 seconds against 859.115 seconds. Logic routing solved 3,037 against 3,124, with summed candidate wall time 936.406 seconds against 830.262 seconds. Neither trial showed a SAT/UNSAT answer conflict or a native runtime error. These are historical observations retained from the session, not raw-row evidence in this commit: maintenance cleared the uncommitted result files and lifting implementation. They do not justify enabling either transformation by default. Shared-machine timeout experiments are also sensitive to scheduling noise.

The mathematical reason lifting is exact does not imply that it is fast. For integers n and positive d, introducing q and r with n = d*q+r and 0 <= r < d uniquely fixes q = n/d and r = n%d under Euclidean semantics. Guarded uses can therefore be represented by fresh variables with unconditional definitions, but declaration freshness, incremental scope and unsupported syntax all require care. Additional variables and constraints can make solver search harder. The current checkpoint does not ship the lost lifting code or claim a new Lean validation of it.

The retained implementation instead studies complementary solver dispatch. A conservative syntax and sort classifier recognizes when a QF_NIA script actually belongs to QF_LIA. Multiplication may have at most one nonnumeral factor; division and modulus require a nonzero numeral denominator. Assertions are unchanged. Sort checking and declaration scope tracking reject unsupported cases. Changing the logic header can change Z3's strategy even though the mathematical formula is the same.

Complementary answers in the earlier trials motivated a fixed-budget portfolio, rather than selecting each file's winner after seeing its timings. For an eligible query, the original strategy receives half of the 250 ms budget. Only an unknown answer activates the alternative strategy for the other half. Both contexts receive every assertion, push and pop so fallback solves the same live problem. Unsupported scripts execute independently through the original strategy with the full budget. Candidate classification and two-context maintenance count toward candidate wall time even if fallback is never used. Fresh paired runs alternate execution order and retain every query answer. Timeout configuration is cleared after each query so it cannot cancel subsequent stack commands.

The new benchmark uses the first eight queries of every one of the 181 files, frozen before timing. It selected 1,439 queries and classified 150 files as eligible. The original solved 584 queries (329 SAT and 255 UNSAT); the portfolio solved 570 (310 SAT and 260 UNSAT). There were 35 paired gains and 49 paired losses, for a net loss of 14 solved queries. Summed wall time was 297.841 seconds for the original and 423.304 seconds for the portfolio, approximately 42.1 percent more. Every stream completed without a native error, and there were zero SAT/UNSAT conflicts. The retained report includes all raw rows. This result rejects default activation of the tested portfolio.

This is a practical checkpoint with complete source coverage at shallow depth. It is neither an independent holdout nor evidence about all incremental states. The shallow prefix overlaps the earlier experiments, while the restored environment uses the solver version recorded in the fresh report. Zero observed SAT/UNSAT conflicts is a consistency check, not a proof of classifier correctness. Larger prefixes or additional strategies should be separate experiments with a fixed declared protocol. The implementation remains opt-in; the original strategy stays the default.

Focused tests cover assertion preservation, rejection of nonlinear and ill-sorted terms, declaration scopes, original fallback, budget validation, and a SAT/UNSAT/SAT incremental sequence. The existing finite-formula and SMT certificate tests are also rerun. These tests establish the specified behavior in representative cases; they do not constitute a whole-repository Lean build or acceptance of a proof by an external verification system.
