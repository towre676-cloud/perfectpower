# Source-bound kernel acceptance for finite SOE machines

The SOE proof compiler now accepts supplied finite deterministic partial machines, rather than selecting one experiment from the retained two-state atlas. Python still discovers the quotient by partition refinement and discovers distinguishing words on the reverse pair graph. Those discovery algorithms remain tested Python. Acceptance is a separate step: regenerate literal Lean definitions from the supplied model and packet, rebuild the generic semantics library, prove observation and transition preservation, prove pair separation, and instantiate `SOESemantics.quotient_complete`. The result establishes equivalence for every finite action word, with no future-depth cutoff.

## Mathematical contract

A machine has a finite state carrier, a finite named action carrier, exact JSON observations, and an optional successor for each state and action. A disabled action maps to `none`. The compiler assigns state indices to `Fin n`, sorted action names to `Fin m`, and distinct canonical JSON observations to `Fin o`. The receipt records the action and observation encodings. In particular, the observation `true` differs from the observation `1`; structured JSON labels are supported without injecting their contents into Lean syntax. Every equality decision in the formal model is equality of these distinct encoded observations.

The packet supplies a partition, its projection, quotient observations, quotient transitions, and a distinguishing experiment for each unordered pair of block representatives. The compiler validates that blocks partition the source carrier and that projection agrees with those blocks. It validates full action coverage, observation preservation, enabled and disabled successors, witness coverage, and each supplied experiment. It does not regenerate a different quotient to silently repair a supplied incorrect packet. A missing, malformed or false witness causes rejection.

Lean receives literal definitions for `obs`, `step`, `q`, `out`, `target`, and `experiment`. Observations and transitions are generated from the source model itself. Quotient definitions come from the supplied packet. The finite proof `observation_preserved` checks all source states. The finite proof `transition_preserved` checks all state/action pairs, including `none` transitions. The finite proof `separated` checks every ordered pair of different quotient classes using its own experiment. The experiment table uses the supplied representative witness in both directions, because inequality of observations is symmetric.

Pair separation is proved on the quotient. For arbitrary source states u and v, `behavior_transport` rewrites the behavior under their class-specific experiment into quotient behavior. This makes the checked quotient experiment distinguish every pair of source states in those classes. Thus representative witnesses suffice even for non-singleton blocks. The existing generic theorem combines these finite obligations with its induction over arbitrary action words to prove `Equivalent step obs s t ↔ q s = q t`. No new assumption about Python refinement is introduced.

The proof checks that every supplied quotient class occurs through the partition preflight. The resulting formal equivalence theorem concerns all source states. The compiler does not claim that hashes, Python table emission, or canonical JSON encoding have themselves been formally verified; these form the binding boundary between an input file and its literal Lean model. Kernel acceptance establishes the theorem about those emitted definitions. Regeneration, recorded encodings and hashes make this boundary reproducible and inspectable.

## Acceptance and public use

`perfectpower.checked_soe.compile_soe(model, packet=None)` returns the generated source, source/packet digest, source digest, encodings, resource limits and packet. Omitting the packet asks Python to propose one. Supplying a packet tests that packet. The compiler never takes a user-supplied Lean proof string as an acceptance input.

`accept_soe(model, packet=None, ...)` regenerates the source and invokes the existing `check_rebuilt` mechanism. That mechanism copies `SOESemantics.lean` into a fresh private directory, compiles it using pinned Lean 4.20.0 and configured Mathlib, compiles an axiom audit of `quotient_complete`, and compiles and audits the generated theorem. It rejects compilation errors, `sorry`, native reduction axioms and axioms outside `propext`, `Classical.choice` and `Quot.sound`. Existing compiled PerfectPower libraries cannot replace the rebuilt semantics module. Lean and configured Mathlib remain trusted dependencies. A missing toolchain, timeout or failed proof never produces `accepted: true`.

The public `soe-states specification.json --kernel-check` command uses this acceptance route and fails the command if the kernel rejects or cannot run. Successful output includes `accepted: true` and `proof_status: kernel_checked`, source and library hashes, encodings and the checked quotient. The ordinary command still provides the existing tested Python result. The receipt's `execution_verified: false` explicitly preserves the distinction between a checked result and a verified Python discovery implementation.

For local use, run `lake env` so Mathlib dependencies populate `LEAN_PATH`, and set `PERFECTPOWER_LEAN=lean`. The `scripts/check_soe_generic.sh` script reproduces source generation, kernel acceptance receipts and focused Python/kernel tests. `python/develop_new_work_lean.py` now routes the retained 324 examples through this same generic compiler and preserves their existing `SOEModelPackets.complete000` through `complete323` names using aliases. The structural-matrix generator is unchanged.

## Resource scope

Input models retain the existing 128-state and sixteen-action ceiling. Canonical model input, canonical packet and generated Lean source each have a two-MiB cap. Each experiment is limited to n squared action symbols; the aggregate witness budget is 100,000 symbols. The Lean query sets 2,000,000 heartbeats and recursion depth 8192. The checker retains its at-most-600-second timeout per subprocess, defaulting to 120 seconds. Limits constrain certificate construction and proof checking, not the infinite family of words quantified in the theorem. A machine within the dimension ceiling can still exceed the source budget or proof resources; such a request fails instead of returning unchecked acceptance. No universal performance guarantee is claimed at the ceiling.

## Reproducibility and rejection evidence

The saved larger models cover a three-state partial machine with delayed observations and disabled actions, a four-state model where different pairs need action a or action b, and a four-state model with three actions, structured observations and a genuine two-state merge. Tests also include a singleton and seeded random three-, four- and five-state models. Input corruption tests cover changed transitions, merged distinguishable states, disabled-action mismatches, unknown schema, malformed packet shape, missing witnesses, corrupted words and source binding changes.

The kernel mutation test deliberately bypasses Python replay. It corrupts generated source successors, disabled actions, projection and experiments, then requires Lean rejection. This tests the independent acceptance obligations, rather than only asserting that Python preflight catches edits. The generated larger examples and their kernel acceptance logs are retained under `PerfectPower/Generated/SOEGenericPackets.lean` and `receipts/soe_generic`. The full retained two-state corpus is regenerated and compiled as a regression check.

This sandbox run used the stock Lean release with a small executable-discovery shim: its process namespace reported a PID whose `/proc/<pid>/exe` entry was unavailable, so `runtime_location.c` substitutes `/proc/self/exe` for that lookup. The shim changes executable location discovery only. Its source, Lean binary hash, pinned Mathlib revision, test counts and reproduction commands are saved in `receipts/soe_generic/reproduction.json` and the adjacent C source. Standard installations do not require that shim.

A direct application can use `from perfectpower.checked_soe import accept_soe` and call `accept_soe(model, saved_packet)` under `lake env python3`. Acceptance returns the checked packet together with its encodings. It is essential to inspect `accepted`, because an unavailable kernel or a resource exhaustion returns rejection. For the command-line interface, `PERFECTPOWER_LEAN=lean lake env python3 -m perfectpower soe-states model.json --kernel-check --out accepted.json` requests the same checked result. `make soe-generic-kernel` reproduces the larger examples, adversarial tests and regenerated atlas; `make new-work-kernel` retains the broader recovered-work closure audit. The Lean CI workflow invokes both targets.
