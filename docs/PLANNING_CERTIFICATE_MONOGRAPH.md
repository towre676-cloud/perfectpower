# Source-bound construction certificates for the Petersen population

## Result and exact status

The complete Petersen 50-project population is **702,508,860,122,761**. The October 15 extension adds a retained, independently replayable construction certificate for the native Boolean decision diagram. The first full replay accepted all five literal resource inequalities, 14,404,146 allocated nonterminal nodes across construction stages, 20,391 threshold-state proofs and 29,187,394 Boolean-intersection proofs. After the producer's existing compaction, the final reachable diagram still has 9,190,151 nodes including its two terminals. Intermediate allocated nodes and final reachable nodes are different quantities.

This is stronger source-bound **external** verification, not a kernel-established theorem about the unrestricted population. The Python checker and its binary parser remain in the external trust boundary. The Lean extension checks local proof rules, a proof-carrying indexed-node constructor, source-chain soundness, and a small native diagram's connection to its literal source predicate. It does not prove that a successful run of the packed Python checker constructs the corresponding Lean evidence. All 59 earlier theorems, the original independent counts, the optimizer witness, and the separate exact optimizer evidence are preserved.

The full standalone audit now includes **99 theorems** across four modules, compiled with pinned Lean 4.20.0. The axiom audit rejects admitted proofs, user axioms and native reflection. The standard logical axioms appearing in individual proofs are listed explicitly in `receipts/planning/independent/lean.json`. This is a standalone standard-library build; it is not a claim that every Mathlib-dependent repository module was rebuilt.

## What the certificate proves externally

A bare node table proves neither that the graph describes the intended resources nor that an asserted root is their conjunction. The trace therefore records the construction dependencies as well as graph edges. Threshold claims identify the literal resource row, suffix level and remaining capacity. Intersection claims identify both operands and the already established low and high conjunctions. A resource-stage record must bind the actual threshold root to that row's original capacity and conjoin it with the previous stage. Five stage records are mandatory for the five-resource instance. The finalization record must identify exactly the final stage root.

The checker receives the public OR-Library data as its independent input. `scripts/check_planning_certificate.py` parses `data/planning/mknap1.txt`, independently selects the requested instance and computes the retained deterministic project permutation. It requires byte-for-byte agreement of every ordered resource cost and capacity in the certificate header. The permutation is retained in the receipt. Sorting by total resource cost changes the coordinate order bijectively; it does not project variables or merge portfolios. The full formal source theorem will also have to account for this permutation, rather than silently identify reordered and original coordinate lists.

`python/perfectpower/planning_certificate.py` does not invoke the planner, the BDD producer, its unique-node hash table or its recursive construction search. It processes the trace in order using packed arrays. It accepts a threshold base only when the remaining capacity is negative (reject) or covers the entire nonnegative suffix sum (accept). A nonbase claim must have both exact successor states, including the selected project's cost subtraction. The missing high successor is therefore not an unchecked pruning assumption.

For an intersection, false annihilation, true identity and equal-operand idempotence are the only implicit base rules. A nonbase proof uses the minimum operand level, obtains each operand's correct cofactors at that level and references the two exact child conjunction proofs. Equal low/high results reduce to that child; unequal results must reference a node with exactly the claimed level and edges. Node identities can be shared, but an arbitrary node with the same numerical population cannot replace a proof dependency.

## Binary format pp-bdd-trace/1

The eight-byte magic is `PPBDD001`. Next are two little-endian unsigned 32-bit dimensions, n and m, then m signed 32-bit capacities, followed by the m row-major cost vectors of n unsigned 32-bit words. The checker supports 0 through 62 coordinates and 1 through 16 resource rows, with nonnegative costs at most 1,000,000. Capacities lie between -1,000,000 and 1,000,000. Negative capacities appear only in the signed header; nonbase threshold residuals are nonnegative.

Every subsequent record is eight little-endian unsigned 32-bit words. The first word is the tag. Reserved words must be zero. Node IDs 0 and 1 are the false and true terminals at level n, with local populations 0 and 1. New node IDs are implicit and increasing, starting at 2. Threshold-proof and intersection-proof IDs each start at 1 and reset at each completed resource stage. Proof ID 0 means only an explicitly checked base case. Native compaction never renumbers certificate node IDs: the producer transports a persistent certificate identity alongside each surviving local node.

| Tag | Remaining seven words | Meaning |
| --- | --- | --- |
| 1 | level, low node, high node, count low word, count high word, 0, 0 | Allocate a nonterminal node |
| 2 | resource row, level, residual capacity, result node, low proof, high proof, 0 | Establish a nonbase threshold state |
| 3 | operand a, operand b, result node, low proof, high proof, 0, 0 | Establish a nonbase Boolean intersection |
| 4 | resource row, threshold root, threshold proof, cumulative root, intersection proof, count low word, count high word | Complete the next resource stage |
| 5 | final root, count low word, count high word, 0, 0, 0, 0 | Finalize the complete resource chain |

For each node at level i with child j at level l, the edge contributes `child_count * 2^(l-i-1)`. Child references must already exist, child levels must be strictly larger, and unequal children are required for an allocated reduced node. A root at level r contributes its local count times `2^r`. Thus skipped coordinates retain original-assignment multiplicity rather than counting paths or distinct resource totals. All arithmetic in the checker uses Python integers and is checked against the appropriate `2^(n-level)` bound; no overflowing native count is trusted.

All five stage counts are checked, not merely the final count. Out-of-range references, forward proof references, variable-order violations, false reductions, wrong threshold states, changed operand identities, missing stages, nonzero padding, manipulated counts, truncated records, missing finalization and trailing records are rejected. Redundant allocations of equivalent unequal-child nodes are harmless and are permitted: global hash-table canonicality is an optimization, not a soundness assumption. A reused reference must denote the exact earlier node required by the local rule.

## Kernel-established intermediate results

`PerfectPower/PlanningCertificate.lean` introduces `CheckedNode`, whose population is proved equal to the existing `weight` evaluator. `skipNode` and `branchNode` preserve these proofs. `checkBranch` rejects a false count label. `StoredNode`, `liftNode` and `checkIndexedNode` add bounded levels and earlier-table references; successful results carry their mathematical population proof. Kernel examples reject missing children, invalid ordering, unreduced nodes and manipulated counts.

`threshold_evidence_sound` proves soundness of bottom-up threshold evidence, including early accepting suffix bounds, over-capacity high branches and predicate-preserving reuse. `conjunction_step_length` proves the binary conjunction step on the exact finite input domain. `SourceChain` and `source_chain_sound` require evidence for every literal row. `PrefixEvidence` and `prefix_evidence_sound` match the binary stream’s chronological resource order and exact previous-root conjunction. `source_bound_population` and `prefix_source_bound_population` connects a checked node with a fully established resource chain to the original feasible predicate. These are generic theorems about supplied mathematical evidence; they do not assert that the packed external trace has already supplied that evidence inside Lean.

The committed native fixture `certs/planning/small.trace` uses rows `[3,4,2,5,1]` and `[2,0,5,1,4]`, with capacities 7 and 5. `scripts/export_planning_certificate_lean.py` translates its shared native nodes into proof-carrying Lean node definitions. `PerfectPower/PlanningCertificateExamples.lean` kernel-checks their literal counts, exhaustively checks source-predicate equality on all 32 assignments, proves pointwise equality for every five-bit input, and proves the original feasible population is **10**. This finite exhaustive bridge is intentionally restricted to at most ten variables and is not a proposed 50-variable truth-table proof.

Run `make planning-certificate-test` for 120 seeded independently exhaustive instances with one through ten variables, zero-cost/skipped-coordinate cases, negative-capacity rejection and the exact `2^62` terminal case. The adversarial fixture tests named corruptions and flips every individual record byte's low bit. A mutation may remain a harmless valid certificate; every accepted mutation must preserve the independently checked population. The existing planning regression suite has 23 passing tests including this module; the separate original standalone verifier still passes 80 exhaustive cases and 320 conditional queries.

Run `python scripts/run_planning_certificate.py --case 20 --certificate /tmp/petersen20.trace --receipt receipts/planning/independent/certificate20.json` for a bounded public-data construction and source-bound replay. Run the same command with `--case 50` for the full instance. The driver compiles the standalone native producer, limits producer address space and wall time, generates a trace, independently checks it, compares results and records source/input/certificate hashes. Default producer limits are 40,000,000 nodes, 600 seconds and 6,144 MiB address space. Replay is linear in the certificate stream, with memory proportional to allocated nodes plus current-stage proof records; it is not constant-memory verification.

Run `python scripts/check_planning_certificate.py PATH --case 50 --receipt RECEIPT.json` to replay an existing raw, gzip or xz trace without rebuilding the BDD. The receipt includes the compressed-file hash where applicable and an independently accumulated hash of the exact uncompressed stream. The retained raw stream is 1,395,583,020 bytes; xz compression reduces it to 394,402,476 bytes (about 3.54 times smaller). Compressed replay also passes in about 182 seconds. Compression is an external storage layer; decompressed records have exactly the same mathematical meaning. Preserve the finalization record and the whole construction history, rather than extracting only the last compact graph.

Run `make planning-population-lean PLANNING_LEAN=/path/to/lean` for the four-module audit. ## Remaining obligation and scalable next step

The full certificate was affordable externally: its first raw replay took about 159 seconds. The expensive unresolved step is **formal replay**, not a need for another population-counting algorithm. The unrestricted theorem must be derived by a formally verified indexed checker or by checked proof terms that establish every trace dependency, source threshold and final conjunction inside Lean. The binary parser, signed-word decoding, reference tables, exact arithmetic, stage resets, compressed-stream identity and original-coordinate permutation must either be verified or eliminated from the trusted path through explicit checked data and proofs.

The current proof-carrying `StoredNode` route materializes structural diagram expressions. It is useful for small source-bound fixtures, but cannot by itself be advertised as a solution to kernel elaboration of tens of millions of trace records. A scalable next implementation should use a verified DAG evaluator and an invariant over packed node/claim tables, retain sharing in the semantic representation, and verify bounded chunks with an explicitly proved state-composition law. Chunks can release current-stage proof tables after establishing a stage invariant. Hashes can bind published bytes to receipts, but a hash is not a substitute for proving the chunk's mathematical correctness.

Until that whole connection compiles and evaluates, the status remains: kernel-proved abstract replay rules and a concrete small source-bound example; externally checked full source-bound certificate; **no kernel-established unrestricted Petersen population theorem**. Global optimizer completeness and uniqueness likewise retain their existing external exact-search evidence rather than acquiring a new formal proof from this counting certificate.
