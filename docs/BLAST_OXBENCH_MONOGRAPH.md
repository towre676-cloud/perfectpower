# PerfectPower on a complete structural-domain benchmark

## Scientific question and evaluation boundary

This experiment asks whether exact mining of BLAST high-scoring segment pairs improves a reproducible biological retrieval task beyond the previous three-record insulin demonstration. The evaluation target is membership in an independently supplied structural-domain reference set, followed by agreement with its conserved residue correspondences. The reference is OXBench, described by Raghava, Searle, Audley, Barber and Barton, *BMC Bioinformatics* 4:47 (2003), DOI 10.1186/1471-2105-4-47. Its reference alignments were constructed using protein structures and structural-domain classifications. Those annotations are external to PerfectPower and are never passed to BLAST, chain construction, chain selection or coverage thresholds. They are used only after searching, to define the evaluation denominator and assess recovered residue correspondences.

A structural-domain benchmark does not supply a complete gene tree. Its sets are therefore treated as annotated positive retrieval sets, not as independently established orthologous gene families. This distinction is necessary because similar domains can appear in proteins with different functions, because proteins can contain several domains, and because structural similarity alone does not distinguish orthology from paralogy. No orthology accuracy, paralogy accuracy, functional prediction accuracy or biological discovery is claimed. The resulting evaluation is a useful independent test of domain-family retrieval and alignment coverage. A gene-tree benchmark with duplication and speciation labels remains necessary before assessing evolutionary assignments.

## Acquisition, annotation and the complete carrier

The retained source is the complete `ox` collection in the publicly distributed `bench1.0` archive at https://www.drive5.com/bench/bench.tar.gz. This collection contains 395 declared set identifiers, 3,292 sequence occurrences and 978 distinct sequence strings. The scope is this particular published collection, rather than every release or variant called OXBench. It should not be confused with the original paper's full Master collection or with the separate extended and MUSTANG-aligned collections in the same download. Every identifier in `ox/info/ids.txt` is processed. Every input and reference filename must agree with that inventory. No families are selected after observing the result, and there is no small-family or favorable-identity subsampling.

The original archive digest, retained subset digest and digest of every retained member are recorded in `data/oxbench/manifest.json`. The retained archive contains raw input FASTA, raw reference FASTA, the original informational files and the distribution README. Historical scores produced by other alignment software are excluded because this experiment does not use them. The acquisition script downloads the original archive with an explicit size cap, checks its pinned digest, reconstructs the subset and requires a byte-identical retained digest. A changed upstream archive is rejected rather than silently replacing the experimental corpus. Offline reproduction uses the retained subset, so future availability of the download is not required.

The source parser checks unique sequence identifiers within each set, equal reference row lengths, exact input/reference identifier agreement, and equality of every ungapped uppercase-normalized reference sequence with the supplied input sequence. Alignment gap markers are removed only for this equality check. Lowercase annotations are preserved. In accordance with the distribution README, uppercase letters define the conserved reference regions used for residue assessment. The normalized search identifiers include both the full source set identifier and an occurrence number; the original protein-domain identifier, length and sequence digest remain recoverable in `records.json`. Several source set names begin with underscores. The implementation uses the explicit mapping rather than guessing family membership by splitting normalized identifiers.

Every occurrence is searched against the pooled carrier of all 3,292 occurrences. That represents 10,837,264 ordered query/subject comparisons, including self comparisons. The positive evaluation denominator consists of all ordered, unequal-identifier pairs within each reference set: 101,750 pairs. Pairs with no returned HSP remain in that denominator. Self HSPs are retained in raw output and source replay but do not count as positive retrievals. Different occurrences can have exactly the same sequence. Accordingly, the receipts also report the number of distinct strings and separate recall measurements after excluding identical sequence pairs and after collapsing repeated nonidentical sequence pairs. These are descriptive normalizations, not a claim that the residual observations are independent.

Cross-set hits are retained in raw output and counted separately. They are not declared false positives. Sets in this benchmark overlap and domain classifications can share relationships, so a different set name is insufficient evidence of nonhomology. For the same reason, this release does not report retrieval precision by dividing within-set hits by every returned hit. Residue precision is a different, explicitly restricted measurement: it evaluates predicted coordinate pairs only when both residues belong to uppercase eligible reference positions.

## Search protocol and BLAST-based baselines

The search uses local BLAST+ 2.12.0, the complete normalized FASTA as both query and subject, E-value threshold 0.001, SEG enabled, and a maximum target count equal to the full occurrence carrier. No maximum-HSP option is supplied, preserving the executable's unlimited default. A standard `blastp` task and a `blastp-fast` task are evaluated independently. Commands, executable version, executable digest, return code, stderr and wall time are retained. Each search has an explicit 600-second local execution limit. A failed or timed-out search does not produce an accepted complete-search receipt. The subject-file execution route is intentionally simple and the retained run uses one thread.

The comparison fixes query coverage at one half. For a query of length L, the integer threshold is the ceiling of L/2. The best-HSP baseline chooses the largest reported bit score, with deterministic annotation-free tie breaking. The any-HSP baseline accepts a pair if any single returned HSP reaches the threshold. The union baseline merges all query intervals, allowing incompatibility on the subject axis. Its coverage is useful as an optimistic envelope but is not a coherent alignment certificate. The ordinary chaining baseline performs a direct maximum-coverage dynamic program on monotone, nonoverlapping HSPs, without producing population polynomials. PerfectPower then constructs the complete same-population suffix polynomial and asks whether any admitted chain reaches the same threshold. Equal-coverage representative chains use summed bit scores only as a deterministic tie breaker. That sum is not interpreted as a combined BLAST E-value.

A coherent chain requires strictly increasing, nonoverlapping query and subject intervals. No between-HSP affine gap score, hidden motif constraint, frame restriction or annotation-dependent edge is added. Consequently the biological candidate population is the same for ordinary chaining and exact population counting. Equality of their maximum coverage is checked for every constructed population. Exact counting is not expected to create HSPs that the underlying BLAST search omitted. A recall improvement over single HSPs can result from combining disjoint fragments; an improvement over a correct ordinary chaining baseline would require an additional, justified decision rule or a different search population.

## Measurements and negative results

The machine-readable results are the task summaries and complete compressed evaluation receipts under `receipts/blast/oxbench`. Each receipt retains every positive pair, including pairs with no candidate, its coverage under each method, the exact qualifying-chain count, the length polynomial, source HSP indices of the representative chain, reference-pair denominator and residue agreement counts. Every BLAST row is replayed against the exact supplied sequences before filtering. The standard search returned 746,322 HSPs and took approximately 278 seconds. Its full output exceeds the earlier tabular parser's 50 MB limit. That first evaluation attempt stopped with an explicit work-limit exception; it is retained as an engineering negative result. The replacement ingestion route reads bounded individual lines and enforces independent row and uncompressed-byte caps. It does not globally disable the ordinary parser's safeguards.

At the primary threshold, standard BLASTP's best-HSP and any-HSP methods each retrieve 73,003 positive pairs. Ordinary chaining and exact chaining each retrieve 73,006. Thus coherent chaining adds three directed pairs out of 101,750, about 0.00295 percentage points of recall. All three additions occur in the source set `___186`. The relevant representative chains cover 230, 232 and 229 query residues respectively, combining two HSPs that individually fail half-query coverage. These are concrete recovered benchmark relationships, not newly discovered biological relationships. The reference supplied those relationships before the search was run.

The unrestricted HSP union retrieves 73,021 pairs. Fifteen of those coverage acceptances fail the coherent-chain criterion. This difference demonstrates the practical distinction between interval union and feasible monotone alignment coverage, but it does not establish that the underlying proteins are unrelated. A pair can be a known domain-family positive while still failing the chosen coherent-coverage decision rule. Exact chaining and the ordinary chaining baseline agree, and no qualifying standard-run population contains more than one path. This particular corpus therefore does not expose a large ambiguous-chain population or demonstrate a biological recall gain attributable to exact counting itself. Earlier exponential synthetic examples remain mathematical scaling demonstrations and must not be substituted for this empirical result.

Standard-run best-HSP residue recall is about 72.180%; the coherent representative-chain residue recall is about 72.184%. Eligible residue precision is about 98.669% for coherent chains. These ratios use 6,285,440 directed conserved reference residue pairs in the denominator. Residue assessment is performed on representative alignments independently of the half-query retrieval decision; it is not conditional on already retrieving a pair. The high precision is restricted to eligible conserved positions and should not be extrapolated to complete proteins, annotation-free discovery or arbitrary databases. Macro family recall and repeated-sequence-normalized retrieval recall are supplied alongside the occurrence-weighted totals. Families and sequence pairs are dependent, so no IID confidence interval or inflated significance claim is reported.

The measured standard-run ordinary chain DP used about 0.90 seconds in aggregate, whereas exact population construction used about 14.50 seconds in the first evaluation. These timings isolate the corresponding Python operations rather than measuring the complete biological pipeline. They are single retained measurements, not a repeated hardware-performance study. They show overhead for retaining complete populations on this largely single-HSP corpus. Exact counting should be chosen when complete candidate multiplicities, coefficients or addressable alternatives are useful, not advertised as a faster replacement for a maximum-only DP on evidence that says otherwise. Updated task-specific timings and the faster-task comparison remain in the final summary receipts.

## The suffix recurrence and finite path language

For a directed acyclic HSP graph, each vertex i has query span c_i. Let F_i(u,v) enumerate all nonempty paths starting at i, with u recording HSP count and v recording additive query coverage. The recurrence is F_i = u v^{c_i}(1 + sum over children j of F_j). The standalone path contributes one monomial. Every longer path has exactly one first successor and is formed by prepending i to a suffix path. Nonoverlap makes the sum of query spans equal to chain union coverage. Distinct successor lists prevent the same vertex path from being emitted more than once; distinct HSP rows still represent distinct candidate vertices even when their biological coordinates coincide.

`PerfectPower/BlastRecurrence.lean` proves this recurrence coefficient by coefficient for an explicit finite path language. Its executable path enumerator has a natural-number fuel parameter. The theorem `mem_paths` characterizes membership as being a nonempty graph walk whose length is bounded by that fuel. A strictly decreasing natural vertex rank bounds every walk, and `complete_language` proves that sufficient rank-derived fuel omits no admitted walk. `paths_nodup` proves uniqueness when every successor list is distinct. Together these results establish the mathematical finite-language meaning of the suffix recurrence and the conditions under which it counts vertex paths rather than duplicated edge listings.

The proof does not certify the Python implementation merely because it uses the same formula. Python's graph construction, dictionary updates, work-limit enforcement and cached polynomial representation remain executable code. This release checks them against independent subset enumeration on retained benchmark populations and checks maximum coverage against an independently written ordinary chaining baseline. A full refinement theorem connecting arbitrary Python execution to Lean is outside the present acceptance boundary. The general theorem modules were found in existing local BLAST certification work, copied without changing their source digests, and compiled afresh here. Their provenance and fresh kernel logs are retained; they are not presented as a newly invented duplicate proof effort.

## Source-adapter acceptance and reproducibility

`PerfectPower/BlastSourceReplay.lean` provides a raw BTOP decoder and a declarative literal traceback relation. A successful decoder acceptance proves valid matching runs, admissible mismatch/gap pairs and consumption of both declared coordinate intervals. The acceptance predicate also checks coordinate bounds. The module proves generic soundness for arbitrary supplied source strings and traces. The bounded generated OXBench input module specializes these obligations to retained literal protein inputs and includes rejected mutation examples. Its checked sample size and exact source rows are recorded, so sample kernel acceptance is never misreported as formal acceptance of all hundreds of thousands of HSPs.

Hash computation, HTTP acquisition, tar and FASTA parsing, statistical BLAST fields, reference-annotation correctness and heuristic search completeness are not proved in Lean. The Python path does check source digests, complete inventory, source/annotation equality, declared lengths, BTOP-derived counts and literal sequence replay. Those checks and the kernel obligations have complementary scopes. Neither makes a BLAST miss impossible. Nor does a complete search over this supplied local carrier establish recall over NCBI nt, nr or every public gene-family member.

Offline reproduction runs `make blast-oxbench-test`, `make blast-oxbench-replay`, and `python scripts/check_blast_oxbench.py`. The last command independently reconstructs residue coordinates from replayed aligned strings, audits every positive-pair denominator and retrieval total, and exhaustively enumerates bounded retained candidate subsets. A configured Lean 4.20 executable can run `python scripts/check_oxbench_kernel.py --lean lean` without compiling unrelated research modules. Live search regeneration uses `make blast-oxbench-live`; acquisition verification uses `python python/fetch_oxbench.py`. The standard library supplies the Python dependencies; BLAST+ and Lean are separately versioned executables. Row, byte, per-pair polynomial-cell, per-search time and per-module kernel time limits are explicit. Unknown work-limit states are retained separately and retrieval recall is accompanied by an upper bound allowing unresolved pairs; no incomplete population is converted into a certified zero.

Integration preserves the BLAST mining extension and the independently newer geometry certificates on main. Publication uses current-head checks rather than overwriting an unexpectedly advanced branch. The complete packaged checkout accompanies this monograph. The scientific conclusion is deliberately limited: the machinery now has a reproducible, externally annotated, complete-carrier evaluation, a supported finite-language recurrence proof and explicit source-acceptance obligations. The benchmark reveals three fragment-combination gains over single HSPs, agreement with ordinary chaining, substantial counting overhead and no demonstrated orthology, biological discovery or recall superiority over the appropriate chaining baseline.
