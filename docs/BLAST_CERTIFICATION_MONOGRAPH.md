# PerfectPower: recurrence, annotation, recall and source certification

This release turns the BLAST mining machinery into a measured, source-bound experiment. Its database is the complete accession set returned by the recorded NCBI Entrez query `INS[Gene Name] AND refseq[filter] AND biomol_mrna[PROP]`: 930 versioned mRNA records containing 628,656 bases. Three retained insulin-family queries produce a universe of 2,790 query/database pairs. Every pair receives an exhaustive local affine score on both subject strands. Every reported HSP receives two independent executable traceback checks. Every database record and external query receives the complete source feature annotation, and the standard-code CDS audit covers every annotated coding sequence. General Lean theorems establish the polynomial recurrence, complete path enumeration under a decreasing rank, absence of duplicate paths under distinct successors, and soundness of the literal BTOP decoder. A separate literal kernel run covers all 624 HSPs from the word-size-28 experiment.

The scope is deliberately precise. The 930-record database is complete relative to one pinned Entrez search response. It is neither all of RefSeq nor a complete catalogue of insulin biology. Gene-symbol search semantics exclude the retained mouse Ins1 query, which is therefore an external query rather than an added database member. The database has two of the three query records, so the reported denominator includes two self pairs. No result in this release claims recall across NCBI nt or nr. Extending the database changes the experiment, its statistical search space, and the reference denominator; it requires a new manifest and a new exhaustive reference run.

Acquisition preserves the original ESearch JSON, its full accession list, all ten GBSeq XML response batches, the separate mouse-query GBSeq XML, and every source digest. EFetch batches must return exactly the requested accession sets. Duplicate records, missing records, unexpected versions, sequence-length disagreements, and altered source bytes fail the corpus loader. The canonical database FASTA is derived from the checked GBSeq sequences and sorted by accession. Raw BLAST outputs are retained losslessly as deterministic gzip streams; source digests bind the original decompressed tabular bytes. XML annotations can change independently of a sequence accession version, so the XML response hashes are necessary alongside accession.version identifiers.

The HSP polynomial addresses a finite population after search. For a fixed query, subject, and orientation, a vertex is a supplied HSP. An edge is an admissible continuation in both oriented coordinate axes. The production constructor requires nonoverlap and order consistency, with optional maximum query/subject gaps and frame congruence. Let c_i be the number of query residues occupied by HSP i. The generating polynomial F_i counts nonempty paths starting at i, using u for HSP count and v for occupied query bases. Its recurrence is

F_i(u,v) = u v^(c_i) [1 + sum over j in successors(i) of F_j(u,v)].

The constant inside the brackets represents stopping after i. Each other term chooses one immediate successor and a suffix path. Prefixing i increases the HSP count by one and the coverage by c_i. With distinct successor lists, the choices are disjoint, and every nonempty admissible path has exactly one such decomposition. Consequently each coefficient counts a path once. Query coverage here is the sum of disjoint HSP spans; it does not charge intervening unaligned bases or treat a large coordinate envelope as aligned coverage. Spacing constraints select admissible continuations but do not impose a new affine gap score between HSPs.

The Lean model starts from an explicit fuel-bounded path language rather than assuming the desired polynomial identity. `coefficient_recurrence` proves the shifted coefficient identity using multiplicity-preserving list counts. The proof uses translated coefficient predicates, avoiding incorrect natural-number subtraction when the requested degree lies below the shift. `mem_paths` characterizes language membership as a graph walk satisfying the fuel bound. `walk_length_bound` proves that strict rank decrease bounds every walk, and `complete_language` removes the fuel restriction at rank(v)+1. Finally `paths_nodup` proves that distinct successor lists produce a duplicate-free path language. Together these results justify the mathematical recurrence for a finite simple DAG, including the coverage dimension.

These theorems do not assert that arbitrary Python code implements the recurrence. The executable `ChainIndex` bridge still requires implementation validation: coefficient accumulation, coverage filtering, score/tie computation, and rank/select are separate obligations. Existing tests compare independent enumeration, separator populations and native CNF counts on bounded HSP problems. The new benchmark adds an independent binomial formula for every suffix coefficient of a complete ordered DAG. The formal result establishes the underlying combinatorics; the executable checks establish agreement for tested bridges and retained packets. Old mining receipts retain their existing scope flags rather than acquiring a blanket kernel-certification label.

The polynomial benchmark uses 8, 12, 16, 40 and 80 ordered HSPs with unit coverage. Every nonempty subset is a chain, so the exact population is 2^n-1 and each starting-vertex suffix has binomial coefficients. Three process-local trials measure index construction; the first three cases also materialize the entire population with an independent recursive enumerator. Counts, suffix coefficients and representative rank/select addresses are checked. The 40- and 80-HSP populations are not enumerated. Their counts are checked against the closed form and their coefficients against binomial coefficients. This distinction prevents a performance demonstration from disguising an omitted exhaustive enumeration.

The small cases matter. At eight HSPs, constructing a polynomial index costs more than enumerating 255 paths. At twelve HSPs, the methods have similar costs. At sixteen HSPs, the index is substantially faster than materializing 65,535 paths. At eighty HSPs, the index represents 1,208,925,819,614,629,174,706,175 chains with 3,240 retained suffix terms. These measurements demonstrate the representation's scaling on a specified synthetic population. They do not establish a speedup for BLAST search, and they do not measure the cost of biological interpretation. Exact timings, all three trials, work counters and runtime metadata are retained in `benchmark.json`.

The independent database reference is a separate C++ implementation of affine Smith-Waterman scoring. It uses match reward 2, mismatch penalty -3, gap opening penalty 5 and gap extension penalty 2, with a gap of length L costing 5+2L. Diagonal, deletion and insertion states search every cell; immediately opposing gaps are excluded in the declared model. Each subject is also reverse complemented, with the complete IUPAC complement mapping. Query sequences in this experiment contain literal A/C/G/T letters. The scanner uses O(subject length) working memory, supplies two scores for every pair, and performs no seed filtering, pruning, E-value calculation or traceback enumeration.

Before the database scan, 123 independently generated and boundary-focused sequence pairs are scored on both strands and compared with the existing exact rational Python solver. All 246 strand comparisons agree. The full database scan covers 1,960,149,408 dynamic-programming cells per repetition. Three full repetitions agree exactly. The reference receipt binds the query FASTA, database FASTA, native source, Python crosscheck source, score model, compiler and optimization flags. This is strong reproducible executable evidence, not a Lean proof of the C++ scanner. Reference-file consumers reject missing or duplicate pairs, incompatible source hashes and incompatible score models.

BLAST+ 2.12.0 runs against a real `makeblastdb` database with `blastn` task, word sizes 7, 11 and 28, masking disabled, reward 2, penalty -3, gap opening 5, gap extension 2, E-value ceiling 1,000,000, one thread and maximum target count 930. The large E-value ceiling is an experimental retrieval setting, not a claim of biological significance. Output includes standard tabular statistics, raw BTOP, source lengths and taxonomy fields. The subject column is explicitly requested as `saccver` and ingested as the canonical versioned subject identifier. Commands, executable version, database-build time, output digests and three search timing trials are retained. No maximum-HSP cap or hidden record truncation is introduced.

Recall is measured for a pair if an independently exhaustive reference score reaches a threshold. A BLAST pair is recovered only when the best supplied HSP, rescored under the declared affine convention, also reaches that threshold. Merely reporting some short HSP does not count as recovery. Every absent pair remains in the matrix with reported score zero. A reported traceback score above the exhaustive reference optimum fails the audit. Undefined recall for an empty positive denominator is represented as null, not as one. Thresholds 40, 100 and 200 are declared before the comparisons and every missed accession pair is retained.

At score threshold 40, there are 2,750 positive pairs. Word size 7 recovers all 2,750; word size 11 recovers 2,653 and misses 97; word size 28 recovers 614 and misses 2,136. At threshold 100, there are 1,850 positives: recovery is 1,850, 1,849 and 614 respectively. At threshold 200, there are 973 positives: word sizes 7 and 11 recover all 973, whereas word size 28 recovers 505 and misses 468. These are exact fractions on the complete finite pair universe, not estimates from a sample of returned hits. They measure retrieval relative to a declared score model, not orthology or experimentally verified function.

Optimal score recovery is also distinct from threshold recall. Word size 7 reports every one of the 2,790 pairs and matches the exhaustive best score on 2,777 of them. Thirteen pairs have a deficit of at most four score units, despite perfect recall at the three declared thresholds. Word size 11 reports 2,710 pairs and reproduces 2,575 exact optimum scores. Word size 28 reports 614 pairs and reproduces all 614 optimum scores it reports, while leaving many reference-positive pairs unreported. This is why a source-valid traceback, a threshold-recovered pair and a complete optimum search receive separate evidence claims.

The measured search/reference workloads differ in output. Word size 7 materializes 157,266 HSP tracebacks; word size 11 produces 4,363; word size 28 produces 624. The reference produces 5,580 scalar strand scores and no traceback population. Three search trials and three reference trials are recorded, with the reference taking a median of about 5.31 seconds, word size 7 about 39.82 seconds, word size 11 about 2.02 seconds, and word size 28 about 0.39 seconds in this environment. Those values describe this corpus and these outputs. They cannot support a general assertion that exhaustive alignment is faster than BLAST. They do expose the practical tradeoff between seed sensitivity, output volume and retained score-threshold recall.

The full annotation comprises 931 distinct source records: the 930 database members and the external mouse Ins1 query. There are 738 organism names and 3,120 source features across those records. Each annotation retains feature key, literal location, all intervals, orientation and every qualifier, including repeated qualifiers. All original XML fields remain available in the hash-bound response files, including fields outside the normalized view. Every HSP in each of the three runs receives query and subject feature projections. Overlapping feature intervals are merged before counting intersecting bases, preventing double counting in joined features. Remote or unrepresentable feature locations remain explicit unresolved states. All local intervals in this corpus are representable.

Projection is a coordinate statement. An HSP overlapping a CDS is not thereby an orthology assignment or a functional discovery. Reverse-oriented hits are projected onto the same original source coordinates, with strand information retained separately. The local database's `staxids` value of zero means taxonomy was not assigned by the local database build; it is not interpreted as a real taxon. Organism, lineage and taxon cross-references come from the checked GBSeq source annotation. Source accession and sequence equality bind these joins. The annotation function rejects query-carrier mismatches, source-length mismatches and tracebacks that do not replay against the annotated sequences.

The CDS audit reconstructs each local coding sequence in annotation order, respects interval orientation and `codon_start`, applies standard genetic code 1, handles its declared alternative initiation convention, and removes a terminal stop before comparison with the source translation. It records trailing partial codon bases and all discrepancies. Here 914 CDS translations agree literally. Nine records contain ambiguous coding letters and eight carry exception/table cases outside the implemented standard translation check. No supported translation discrepancy was found. Those seventeen unresolved cases are retained with their exact qualifiers and statuses. Their existing source annotations remain available; the audit does not upgrade predictions to experimental facts.

Source-adapter certification has three layers. The production ingestion checks tabular counts, coordinate spans, percentage rounding, source lengths and BTOP grammar. Production replay compares every matching run, mismatch residue and gap operation with the supplied source intervals. An independent character scanner then checks the same raw BTOP using its own parsing and feature accumulation. Across all three runs, every one of 162,253 HSPs passes both executable replay paths. The word-size-7 output exceeds the normal 100,000-row ingestion budget, so this experiment declares a 200,000-row budget in its receipts. Exceeding a budget raises an incomplete-work error rather than returning a truncated successful population.

The Lean BTOP decoder is a third implementation with declarative trace semantics. `replay_sound` proves that successful decoding constructs a valid trace derivation, including bounded identical runs, valid residue pairs, permitted gaps and complete interval consumption. `acceptance_bounds` proves accepted input coordinates lie within both literal sources. `acceptance_valid` joins source interval extraction to the declarative traceback semantics. The literal word-size-28 certificates instantiate this decoder on all 624 raw traces and their full source sequences in thirteen batches. They use kernel reduction, not `native_decide`. A separate encoding validator compares all generated source literals and HSP tuples with the original FASTA/tabular inputs before compilation.

Sixteen new-source modules are freshly compiled in Lean 4.20.0: the two generic modules, the literal source carrier, and thirteen literal traceback batches. The axiom inventory contains only the normal whitelisted logical foundations where needed; no `sorryAx` or compiler-trust axiom is accepted. Literal batch proofs list only the standard propositional-extensionality axiom. The word-size-7 and word-size-11 experiments are completely executable-audited but are not claimed as literal kernel runs. The generator can request either of those complete runs explicitly; it imposes no silent sample cap. Python FASTA/XML parsing, SHA-256, NCBI server authenticity, score-DP correctness, biological annotation truth and all downstream statistical interpretation remain outside these kernel theorems.

The offline explorer exposes the complete recall matrix, threshold and word-size controls, query and organism filters, missing-pair views, exact score deficits, per-record source features, CDS audit status, benchmark populations and full receipt download. It does not require a live database or a network request. The CLI supplies `certify-source`, `annotate`, `recall` and `certification-report`, accepting retained compressed source files where appropriate. `make blast-certification` recomputes the finite experiment from retained bytes; `--run-blast` explicitly repeats the live local executable searches. Network acquisition is a separate explicit command, so a reproduction never silently refreshes the database.

The relevant primary references are NCBI's E-utilities parameter documentation at https://www.ncbi.nlm.nih.gov/books/NBK25499/, the BLAST command-line parameter and output-format appendix at https://www.ncbi.nlm.nih.gov/books/NBK279684/, and NCBI's account of seed sensitivity at https://blast.ncbi.nlm.nih.gov/doc/blast-topics/blastsearchparams.html. They explain the acquisition and search interfaces; they do not certify this implementation. The retained sources, complete pair receipts, independent audits, regression tests and fresh kernel logs provide the evidence for this release. Its practical contribution is a reproducible way to connect polynomial populations to real BLAST outputs while keeping mathematical correctness, source agreement, search recall and biological meaning separately inspectable.
