# Exact graph methods for PerfectPower

**What this release adds.** Graph structure is now an executable part of PerfectPower. The new interfaces count finite factor models, expose their solution populations, construct maximum bipartite matchings with Hall obstructions, construct integral maximum flows with matching cuts, compute cellular homology, analyze finite action machines, and measure exact winding of planar strings. These operations live in the existing Python package and main command line. They use integer or rational arithmetic and require no additional Python dependency. The work was motivated by Reinhard Diestel's *Graph Theory*, electronic second edition (2000), especially §§1.9, 2.1, 6.2 and 12.3: https://www.cs.unibo.it/babaoglu/courses/cas00-01/tutorials/GraphTheory.pdf. The implementation is original code; the textbook supplies mathematical foundations rather than implementation text.

**The counting model.** A model declares a finite integer domain for every variable and a list of factors. A factor records an ordered variable scope and a nonnegative integer weight for each tuple in the Cartesian product of those domains. The answer is the sum, over complete assignments, of the product of their factor weights. Indicator factors represent ordinary membership constraints. Integer weights additionally represent multiplicities, but the rank and population interfaces deliberately require indicator factors so one original assignment corresponds to one object. Table order follows the declared domains and scope, including unsorted domains and scopes. Empty factors contribute their constant weight; variables absent from every factor still contribute their domain size.

**Separators and elimination.** Variables occurring in one factor form a clique in the primal graph. A deterministic min-fill heuristic chooses an elimination order. Each eliminated vertex and its remaining neighbors form a bag; the bags are connected into a forest through their earliest later neighbor. A replay checker checks vertex and edge coverage, acyclicity and running intersection. The reported width is an upper bound from this order, with no minimum-width claim. During elimination, all factors containing the current variable are multiplied, the variable is summed out, and the resulting table is retained on its separator. The result is exact because every operation is a finite distributive rearrangement of the original sum. Distinct components ultimately contribute separate scalar factors whose values multiply.

**Reuse and limits.** Equivalent local elimination problems reuse a message even when their original variable names differ. The cache key preserves local domains, the eliminated position, ordered factor scopes and every factor value. This is reuse of an identical finite arithmetic operation, rather than an unproved graph-isomorphism guess. Assignment visits and retained separator-table entries have separate checks against the supplied cell budget. CNF table construction has a budget too, and decomposition search has a structural work limit. Exceeding a limit raises an exception and returns no exact answer. These limits do not eliminate exponential worst-case behavior: a wide bag, a long clause, or a large finite domain can make the method unsuitable.

**Original-coordinate populations.** `GraphPopulation` provides count, select, rank, restriction, marginal counts and uniform sampling through a uniformly chosen rank. Assignments are ordered lexicographically by variable order and by each declared domain order. Restriction slices every affected original factor table and retains the original variable carrier. Select conditions successively on candidate values and skips entire counted blocks. Rank sums preceding blocks along the same path. These queries avoid enumerating all solutions, although they run several eliminations and their budgets apply separately to each run. Exact polynomial predicates can be compiled into finite indicator factors with `predicate_factor`. This bridge covers the explicitly supplied domains; it establishes no global bound on an infinite Diophantine family.

**Matching and explanations.** The matching implementation uses augmenting paths and constructs alternating reachability from unmatched left vertices. It returns a matching and a vertex cover of equal size. The separate checker verifies the matching's distinct endpoints, all edge memberships, coverage of every edge, and equality of matching and cover sizes. These facts certify maximum cardinality. If the left side cannot be saturated, it also returns a set of left vertices and their exact neighbor set with fewer neighbors than vertices. `distinct_assignment` translates that obstruction back to the original allowed integer values. This is useful for all-different constraints, allocation and scheduling. It does not justify deleting choices from problems without a distinctness condition.

**Flows and optimality.** Integral capacities are attached to directed arcs; parallel arcs are aggregated and antiparallel arcs are supported. Edmonds–Karp uses antisymmetric net flow internally and outputs a nonnegative directed flow matrix. A separate checker checks every capacity bound, conservation at every vertex, terminal value, the supplied terminal cut and equality of cut capacity and flow value. That equality certifies optimality without rerunning augmenting paths. The implementation solves the declared capacity network. Power-grid equations, chemical reactions and physical transport laws must be modeled separately before this result can describe those systems.

**Topology, including torsion.** A spanning forest constructs an integral fundamental cycle basis for a multigraph, retaining loops and parallel edges. Supplied faces are signed integer edge chains; their boundaries must be cycles. Rational row reduction computes Betti numbers and representatives of first homology. Face coordinates in the integral fundamental basis reconstruct every original face boundary exactly, and the existing Smith reduction supplies the integral first-homology quotient, including torsion invariant factors and its replayable transcript. Thus a graph loop can disappear after a disk face is attached, while a twice-wrapped face yields a Z/2 torsion class. A triangular-mesh adapter consumes the repository's contiguous vertex IDs and optional face orientation signs. These are cellular invariants of the supplied complex. Manifold validity, smooth metrics, certified analytic periods and physical geometry are separate questions; the existing oriented-surface and symplectic machinery remains available for its stronger input contract.

**Finite machines and strings.** The machine adapter retains directed, action-labeled transitions, shortest access words, reachable and unreachable states, an undirected structural decomposition and the existing future-behavior quotient. The undirected graph is used only for structural analysis; it does not replace directed action semantics. The string adapter computes winding numbers of closed rational polygons around supplied point objects using exact orientation tests. Points contacting a segment are rejected because winding is undefined there. Positive, negative and repeated winding are retained. This is an integration primitive for STRING's wrapping mechanic, not a physical grasp model, executable update or inference about open strings. The release changes PerfectPower; other repositories and the Windows STRING executable were not modified.

**Formal scope.** `PerfectPower/GraphCertificates.lean` builds with Lean 4.20 and its standard library. It proves independent weighted-population multiplication, accumulation of pointwise bounds, a cut upper bound with an explicit cut-balance premise, and optimality from an attained universal bound. Kernel reduction additionally checks finite CNF, matching and flow examples. `graph_lean.compile_cnf` emits a source-bound theorem counting all Boolean assignments of supplied clauses, with an explicit small assignment limit. The saved CNF fixture is accepted by Lean, and a deliberately changed answer is rejected. This finite enumeration route does not prove the general Python separator compiler, JSON parser, matching algorithm, flow algorithm, winding code or Smith implementation correct. General runtime certificates use exact Python replay; kernel-checked claims refer only to the saved formal statements and fixtures. The axiom report uses standard Lean axioms only, with no `sorryAx` in accepted declarations.

**Validation and performance evidence.** Seventeen focused test methods include 320 random CNF comparisons against exhaustive assignment enumeration, 80 weighted finite-model comparisons, exhaustive small matching optima, 245 random flow comparisons against every terminal cut, adversarial certificate mutations, rank round trips, conditioning, domain-order checks, winding/contact cases, and homology examples for a disk, sphere, torus and torsion complex. The retained large exact case has 200 Boolean variables in 100 independent two-variable positive clauses. Its count is 3^100; local-message reuse reduces evaluated assignments to fewer than twenty. Related surface, SOE and graph-metric regressions are recorded separately. Kernel acceptance and rejection logs accompany the examples.

**Benchmark interpretation.** The benchmark contains twelve synthetic cases: three chains, three disconnected formulas and six random dense formulas. It compares the separator counter with an independently implemented internal cached DPLL with unit propagation. Both answers agree in every case; five timings per implementation and case are retained, together with their medians, seeds, widths and table statistics. The disconnected examples favor separator reuse strongly, while the dense examples favor DPLL. Aggregate time is dominated by the larger disconnected reference searches and does not establish broad superiority. This is neither a comparison against Ganak or D4 nor a rerun of the industrial SMT corpus. Raw results live in `receipts/graph_methods/benchmark.json`; timings are measurements of this machine, not a contractual performance claim.

**Reproduction.** From the repository root, `make graph-methods` tests the implementation and regenerates the examples. `make graph-methods-benchmark` regenerates the synthetic comparison. With Lean 4.20 available, `make graph-methods-kernel` checks the foundation and the generated CNF theorem; `PERFECTPOWER_LEAN` can name an installed executable. The integrated command `python -m perfectpower graph flow examples/graph_methods/flow.json` returns a value-five flow and equal cut. Replace `flow` with `cnf`, `matching`, `machine`, `homology` or `string` and use the corresponding example file. The same operations are available through `perfectpower.graph_cli`. The public Python modules expose factor models, queryable populations and predicate compilation for applications that already supply finite arithmetic constraints.
