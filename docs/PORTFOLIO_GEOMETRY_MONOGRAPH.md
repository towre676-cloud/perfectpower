# Geometry for exact portfolio populations

The Geometric Observatory links the original Petersen project coordinates to the actual portfolio engine. Its rotatable resource prism displays a chosen three-resource projection of all 50 original projects. The translucent box shows the corresponding lower and upper resource bounds. A gold ray identifies the focused project. When a completed engine query supplies a selection, its exact resource sum becomes a violet endpoint, and a cumulative path adds its chosen projects in original order. Orbit, zoom, project picking, a keyboard-accessible project selector, axis swapping and reset support inspection without command arguments.

The point set consists of individual projects. It is not an enumeration, convex hull or reconstructed shape of the 702,508,860,122,761 feasible portfolios. The three-resource box provides necessary projected bounds; the engine still enforces all five resources. No membership conclusion or population count is inferred from a location inside that box. Project bubble sizes encode the square root of positive objective score only as a visual cue. Original score and cost values remain visible in the inspector.

For a selection x in {0,1}^50, the displayed resource vector is the exact integer sum u_k(x) = sum_j c_jk x_j. The cumulative path uses the original project order and has endpoint u(x). Its intermediate points describe the order of summation, not a scheduling model or a guarantee that every intermediate prefix satisfies lower bounds. A three-axis projection selects coordinates of that same five-resource vector. Resource scales are chosen to keep bounds, project points and the selected vector visible; they are stated on the axes.

The five-resource footprint combines the focused project, the resource ceilings, the lower bounds, and the computed portfolio. Each spoke is scaled independently, so its silhouette describes relative usage within the current display rather than a Euclidean comparison between different physical resource units. The exact adjacent table prevents the drawing from replacing numerical values. The expandable 50-by-5 coordinate matrix retains every original project identity and cost.

The Decision lens uses only actual conditional completion answers. For a fixed original prefix q, the original next-project branches satisfy C(q) = C(q0) + C(q1). The renderer derives proportional widths with integer division before conversion to plotting coordinates. Specifically, its drawing share is floor(10000 C(qb)/C(q))/10000 for a nonempty parent; empty parents receive zero width. Labels display full arbitrary-size integer populations and their actual conditional maximum. A drawing width rounded to zero is not a claim of a zero exact count. No synthetic child population is generated while a query is running or unavailable.

The native workspace follows fresh completed planner results and edited resource bounds. Changing bounds clears the old plotted selection; returning to original bounds also clears it. Rendering and project inspection remain available while the exact engine computes. A continuous render loop pauses expensive rendering outside the viewport or while the document is hidden. Orbit begins only when requested and respects the operating system's reduced-motion setting. Disposing the workspace releases mesh geometries, labels, textures, renderer, observers and controls. A missing WebGL context leaves the exact inspector, SVG footprint, Decision lens and coordinate matrix available.

The browser/phone companion shows retained exact results from the root computation and the recorded case excluding original projects 1 through 26. It identifies these as retained computations and directs fresh resource queries to the native engine. Its exporter binds original input and compressed receipt hashes and independently recomputes selected resource use, selected objective scores, inclusive-bound feasibility and conditional branch sums. It does not provide a new independent unrestricted counting computation.

The numeric engine is unchanged by this visualization release. Display coordinates use floating-point numbers; counts, labels and portfolio sums remain exact. The retained arithmetic checks cover populations beyond JavaScript's safe-integer range. Browser workflow checks exercise 3D initialization, project selection, axis swapping, orbit controls, real native computation, conditional diagrams, the complete coordinate matrix, responsive layout and disposal without uncaught JavaScript errors. These Chromium software-WebGL checks are not physical Windows or Android device tests.

The complete source includes the same geometry implementation for desktop and Android, along with the browser companion and deterministic data exporter. An installed native package needs updated UI assets to display the new workspace. A live research update is not an APK upgrade; the Android executable remains dependent on the existing private update signing key. Native and hosted publication identities are recorded separately in release receipts.
