# Structural counting study, 0.10.2

The paired baseline is 0.10.1, commit
`d4dc8dc6fa5ba5f6c6f11e81ccd766e1d3bdf3cc`. Both competition corpora have
already been inspected and used for development. Neither is a blind holdout.
The following protocol is fixed before the full structural screen.

## Implemented scope and literature

Lagniez and Marquis, **Preprocessing for Propositional Model Counting**,
AAAI 2014 ([author copy](https://www.cril.univ-artois.fr/~marquis/lagniez-marquis-aaai14.pdf)),
motivates recognizing functional gates and removing their output variables.
Lagniez, Lonca and Marquis, **Improving Model Counting by Leveraging
Definability**, IJCAI 2016
([paper](https://www.ijcai.org/Proceedings/16/Papers/112.pdf)), explains why
unique extension, rather than ordinary satisfiability preservation, matters.
The implementation recognizes complete syntactic signed AND gates and performs
bounded, sequential Davis–Putnam resolution. It does not implement general SAT
definability discovery, the full B+E preprocessor, or semantic gate discovery.

Dechter's **Bucket elimination: A unifying framework for reasoning**,
Artificial Intelligence 113 (1999)
([author copy](https://ics.uci.edu/~dechter/publications/r76A.pdf)), informs the
exact sum/product evaluator retained from previous releases. A sparse filled
primal graph now extends greedy minimum-degree planning beyond 256 variables.
Sang, Beame and Kautz, **Heuristics for Fast Exact Model Counting**, SAT 2005
([author copy](https://www.cs.virginia.edu/~rmw7my/papers/sat05-wmc-sang-beame-kautz.pdf)),
was also reviewed; no new branching heuristic from that work is claimed.

## Counting argument and operational bounds

Let F be a formula on a declared universe V containing the complete gate
G defining signed output t as the conjunction of signed inputs. For each
assignment to V without the output variable y, G permits exactly one y.
Full resolution on y produces R equivalent to existentially quantifying y
from F. Therefore restriction is a bijection between models of F and R,
and their model counts are equal. Removing y contributes one extension.
Deleting any other variable merely because it disappeared from clauses would
be unsound: those variables stay in the active universe and may become free.

Each accepted step generates every positive/negative resolvent, deletes
tautologies and duplicate clauses, and removes one output. Steps are sequential;
individually defined outputs are not eliminated simultaneously without checking
their dependencies. Original-variable assumptions are applied before reduction
for every conditional query. Rank and select retain their original coordinates.
This is an implementation argument tested independently, not a Lean certificate.

Gate reduction runs only at search depths zero and one, on at most 8192 active
variables and 50000 clauses. Gate clauses have length 3–9; positive/negative
occurrence products are at most 64; new resolvents have at most 12 literals.
Distinct clause count and total literal count may not increase. Each invocation
accepts at most 512 outputs. These bounds limit attempted work, not a theorem
about optimal preprocessing.

Sparse planning applies to 257–8192 variables, with at most 400000 initial
directed primal edges. The existing scope bound of 18 and estimated-state
budget of 8000000 remain. At most eight large-planner attempts are made per
query, at any search depth. Minimum-degree ties use variable ID. Sparse fill
models exactly the scopes generated by bucket elimination; the order is a
heuristic and does not compute optimal treewidth. Exact arbitrary-size integer
factor evaluation is unchanged. Deadlines and external memory limits remain.

## Full comparison and follow-up rules

Run all 200 MC2025 Track1 public-draft instances against the paired baseline,
Ganak 2.8.0 with `--prob 0`, and the archived D4 2024 entry. Run all 200 MC2024
instances against the paired baseline. Both primary screens use five seconds
and 6 GiB per process. Startup, parsing, construction and counting are timed;
native compilation is warmed separately with the same Boost headers for both
PerfectPower versions. These references do not establish a comparison against
the current 2026 champion.

Freeze and hash both native sources and libraries, Python sources, execution
and comparison runners, manifests, and reference binaries. The existing serial
lock prevents overlapping comparisons. Rotate solver order and checkpoint each
completed case. Retain all declared cases, failures, timeouts and mismatches.
Any exact-count disagreement stops the comparison.

After each screen, repeat the union of instances solved by either PerfectPower
version three times at the same five-second budget. MC2025 repeats include both
references. Selection includes regressions; it is descriptive, not independent
evaluation. Repeat all 13 MC2025 instances previously solved in 0.10.1 at fifteen
seconds against the paired baseline, separately from the primary score. Every
current exact answer without an independent reference count receives a separate
thirty-second reference comparison. Longer budgets never replace primary failures.

Post-screen single-feature ablations disable gate reduction or sparse planning
on explicit observed gains and jointly solved cases, with three trials and ten
seconds per variant. Preserve variant source and binary hashes and validate
every exact answer against the screen. Selected ablations explain mechanisms;
they are not an unbiased solver ranking.

Report coverage, gains and losses, all-case PAR-2, and paired descriptive
instance-cluster bootstrap intervals. Jointly solved speed ratios exclude
failures only from that conditional statistic. Report the known normalized
52-instance overlap between the two corpora separately; remaining instances
are not certified semantically or family independent. Public receipts contain
portable counts, times and hashes; detailed logs remain in the private handoff.
