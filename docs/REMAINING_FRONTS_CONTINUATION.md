## From cluster conductors to local component groups

`semistable_tamagawa.py` takes a connected metric graph, constructs an integral cycle basis from a spanning tree, and forms its monodromy pairing G=C diag(lengths) C^T. A chord has coefficient one in its own cycle, so the basis is primitive without an unrecorded rational saturation step. Positive lengths make the pairing positive definite on cycles. The checker requires an integral pairing over the declared base field. Smith normal form gives the invariant factors of the geometric component group Z^r/G Z^r, of order det(G). Bridges and genus decorations do not contribute additional cycle generators.

The local Tamagawa number is not generally this geometric order. The caller may supply a signed edge permutation and a vertex permutation. The code checks every incidence, orientation, length and integral cycle identity. If columns of cycles transform by A, the dual discriminant quotient transforms by T=A^(-T). Its fixed subgroup has the same order as the cokernel of T-I on that finite group. Therefore the local number is the lattice index determined by the Smith form of the rectangular presentation [G,T-I]. This computes invariants without enumerating an enormous group. Without a supplied or derived Frobenius action, the generic graph interface returns the geometric group and leaves the local number unspecified.

The curve adapter derives that action for semistable hyperelliptic curves with rational branch roots at odd primes. For an even cluster s with rational center z_s it forms c times the product of z_s-r over roots outside s, removes its valuation, and computes the Legendre symbol of the remaining unit. This is the residue-field sheet character. Odd edges have one lift; even edges have two, swapped precisely for the negative character. Two-sheet vertices transform likewise. The resulting action is checked as an automorphism of the actual lifted graph before the component-group calculation runs. Ramified sheet characters, nonsemistable inputs, extension-field root specifications and p=2 are rejected by this adapter.

The independent tests include elliptic split and nonsplit multiplicative families y²=x(x-p^d)(x-1), theta graphs, subdivision into regular unit edges followed by a Kirchhoff determinant, and explicit finite-group enumeration of Frobenius-fixed cosets. At p=5 the untwisted elliptic family has geometric and local number 2d; its nonsquare twist has the same geometric order but local number two. The three-twin genus-two example at p=3 has component group Z/2 times Z/6; its local number is 12, falling to four under the nonsquare twist. Sixty independent random theta-length tests check both the subdivided graph determinant and fixed-coset count. Fifty-seven curve receipts retain the complete pairings, characters and outputs.

This is a concrete partial closure of N41: integral semistable metric graphs and rational-root odd-prime local numbers are executable. It does not construct minimal regular models for arbitrary curves, derive arbitrary Frobenius actions from extension-field clusters, or handle dyadic and wild ramification. The arithmetic interpretation uses the established semistable graph/monodromy theorem of Dokchitser, Dokchitser, Maistret and Morgan, *Semistable types of hyperelliptic curves*, https://arxiv.org/abs/1704.08338. This is an implementation of that bridge, not a claim to have discovered the component-group theorem.

## Resonances beyond two dimensions

`resonant_frobenius.py` handles xY'=(R+E x/(1-sigma x))Y in arbitrary supported rank up to twelve, in a supplied rational constant Jordan frame R=D+J. The diagonal D contains rational exponents; J commutes with D and must be nilpotent. Supplying a generic matrix with an unrelated diagonal does not qualify: the checker rejects it. Automatic algebraic eigenframes and irregular singularities are separate tasks.

It constructs an analytic gauge H=I+sum H_n x^n and a polynomial normal form B=R+sum N_n x^n. The coefficient equation is

\[
(nH_n-RH_n+H_nR)+N_n
=\sum_{k=1}^{n}A_kH_{n-k}
 -\sum_{k=1}^{n-1}H_{n-k}N_k,
\qquad A_k=E\sigma^{k-1}.
\]

Only entries with exponent difference d_i-d_j=n may contribute to N_n. The checker fixes the resonant gauge entries to zero and records the resulting obstruction there. On every other weight block the Sylvester operator is invertible, including the nilpotent Jordan contribution. Every coefficient is solved over exact rationals. An independent replay verifies xH'=AH-HB coefficient by coefficient. The order must exceed every positive resonance; a truncated computation that has not reached a later obstruction is rejected.

Set N=J+sum N_n. Since each nonconstant N_n raises the exponent by the positive integer n, and each equal-exponent Jordan block is nilpotent, N is nilpotent. The solution is Y=H x^D exp(N log x), with a finite logarithm polynomial. Integer resonance gaps make exp(2 pi i D) commute with N, giving local monodromy exp(2 pi i D) exp(2 pi i N). A rank-three chain produces log², and a rank-four chain produces log³; these cannot generally be represented by a two-dimensional one-log chart. Repeated-exponent Jordan blocks are included as well. An explicit log² solution is differentiated independently in the tests.

The analytic gauge tail has a separate exact rational majorant. In maximum-entry norm the Sylvester perturbation is bounded by 2 rank max|R|. Beyond an explicitly checked cutoff, its inverse is bounded by 1/(n-2 rank max|R|). Choose a growth s>|sigma|. The geometric convolution contributes rank max|E|/(s-|sigma|), and the finite normal-form correction contributes sum rank max|N_k|/s^k. The cutoff exceeds this total plus the Sylvester perturbation. Induction then bounds |H_n| by M s^n, where M is computed from the retained prefix. At 0<r<1/s the omitted gauge tail is at most M(sr)^order/(1-sr). A scalar closed-form solution (1-x)^(-3) independently tests this bound. This certifies H's analytic tail; endpoint invertibility and the size of x^D and logarithms need their own enclosures.

The new interfaces are reachable through the exact query protocol as `semistable_tamagawa`, `metric_component_group`, `resonant_frobenius` and `frobenius_gauge_tail`. N42 now has higher-rank regular-singular resonance machinery and analytic gauge tails. Algebraic eigenframes, irregular exponential factors and Stokes matrices remain open.

## Concurrent execution and independent replication

The reference server remains a single query worker using one catalogue connection. A synchronized burst test compares every request's HTTP status, request identity, exact JSON payload and error with independent serial dispatch. It also reopens the persisted catalogue after server shutdown. The workload mixes counts, ranked selection, pages, definitions and deliberate errors. In the initial test the default five-connection accept queue caused resets at sixteen and thirty-two concurrent clients. The queue is now 128. Four workloads of 384 requests, with 1, 8, 16 and 32 clients, pass exact replay with no transport failure; a second 1,536-request run passes too. This resolves the demonstrated burst-queue failure and supplies the requested reference-server load test. It is not a multi-worker throughput or distributed transaction claim.

The industrial replication reacquires the pinned SMT-LIB submission corpus and verifies all 181 Git blobs and SHA-256 hashes, totaling 307,442,420 bytes. It uses the established frozen eight-query prefix cap, 250 ms per query, three worker processes and alternating paired solver order. Across 1,439 queries the original resolves 571 and the portfolio 540. The portfolio gains thirty previously unknown answers but loses sixty-one resolved answers. There are zero SAT/UNSAT conflicts. Summed wall time is 313.84 seconds for the original and 466.40 seconds for the portfolio, approximately 48.6% more. This independently reproduces the unfavorable direction of the earlier experiment. The portfolio remains opt-in. The complete query ledger is `receipts/industrial_replication_20261008.json.gz`, with an uncompressed summary beside it. Timings and timeout outcomes depend on hardware and scheduling; the retained per-query ledger supports this measured result, not a universal slowdown theorem.

## Browser execution and reproducibility

Dresden's exact numerical operations are CPU BigInt/rational TypeScript. Three.js uses WebGPU or WebGL for presentation; the current code contains no GPU numerical kernel whose answers could be compared with Python. The new Chromium runner executes the existing independent Python-fixture suites inside an actual browser rather than only Node. It additionally requires the real Three.js scene to initialize, reports the chosen backend and canvas dimensions, and fails on page exceptions. Software-adapter execution is explicitly distinguished from physical GPU performance. Two software WebGPU attempts passed the arithmetic fixtures but failed the strict page-error check with “Instance dropped in popErrorScope”; this failure is retained in `receipts/dresden/webgpu-attempt.json`. The successful fallback receipt records WebGL 2 execution and the completed fixture suites. A successful WebGPU software or physical-device run remains open. Browser package installation is external to the mathematical results.

Run `PYTHONPATH=python python python/develop_remaining_fronts.py --http` to regenerate the declared-wall seed when absent and check it at 160 and 192 bits, regenerate the 57 curve and three resonance receipts, and repeat HTTP replay. Add `--regenerate-wall` to propose a new SciPy seed; this proposal is accepted only after the same interval inequalities pass. `python/tests/test_remaining_fronts.py`, `test_declared_wall_certificate.py`, `test_wall_stability_certified.py`, `test_wall_profile_intervals.py` and `test_applications.py` cover the changed machinery and its neighboring interfaces. NumPy/SciPy/SymPy and python-flint are needed for the research calculation. The industrial run additionally needs z3-solver and the externally materialized corpus; its exact invocation is `python industrial_performance/run.py --corpus PATH --cap 8 --timeout-ms 250 --workers 3 --output receipts/industrial_replication_20261008.json`.

For Chromium, install the frontend dependencies and Playwright, then run `DRESDEN_GPU_BACKEND=webgl DRESDEN_START_VITE=1 node web/dresden-observatory/tests/browser-parity.mjs`. `CHROMIUM_PATH` selects an existing executable and `PLAYWRIGHT_MODULE` may select an external package installation.
