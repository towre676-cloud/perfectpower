# Dresden numerical research with PerfectPower

## The delivered research object

This release turns declared Dresden-related numerical models into exact executable objects. It supports canonical Long Count conversion, caller-anchored Calendar Round conversion, noncoprime congruence intersections, bounded count and rank selection, source-linked alternative readings, original-day polynomial restrictions, declared Venus correction recurrences, exact long-horizon error envelopes, and complete interval-sum reconstruction inside an explicit finite candidate vocabulary. It reuses PerfectPower's semilinear population counting and polynomial/Sturm domain engine. There is no requirement that the historical integers be perfect powers.

The source modules are `python/perfectpower/dresden.py` and `python/perfectpower/dresden_eclipse.py`. `make dresden` regenerates `receipts/dresden/corpus.json`; `make dresden-test` exercises the new layer. The interface accepts JSON from a file or standard input: `PYTHONPATH=python python -m perfectpower.dresden research/dresden/venus_request.json`. It also imports as an ordinary standard-library Python module. No additional runtime dependency is introduced.

This release combines numerical foundations with complete extraction of selected published tables: 69 eclipse stations, 260 Venus ritual numbers and 8,052 modeled lunar appearances. Published numerical figures have been transcribed; the manuscript itself has not received a complete independent glyph transcription. Candidate-reading and missing-interval demonstrations remain synthetic. Numerical eclipse restart components and interval distributions are implemented, while historical eclipse visibility is not independently validated. Mean-period Venus comparisons are arithmetic experiments rather than ephemeris predictions. The current release adds nineteen Lean model theorems and three concrete audit examples, with a separate exact browser polynomial explorer. End-to-end interpreter verification remains open.

## Manuscript structure and evidence

Every numerical interpretation needs an evidence record that identifies its source and manuscript location. `solve_alternatives` requires each reading to carry an ID, residue, modulus, source and location. Independent inscriptions each provide a list of alternative readings. The solver considers every combination, intersects its congruences, and retains each compatible assignment with the exact bounded population it describes. Assignments remain separate even if they describe overlapping or identical dates. Their counts must not be added to obtain a distinct-day union.

The Wikipedia overview was examined section by section. Description motivates page/register/column addresses. History motivates separating proposed origin, copying date, European acquisition and interpretation history. Image motivates a manuscript-wide sequence map. Deterioration and pagination motivates preserving witness-specific page order and damaged readings. See also supports comparisons with other codices. References and Bibliography supply source leads; Further reading broadens interpretive context; External links and Video offer facsimile and public-explanation routes. This release records those roles without claiming that bibliographic references have all been read or that images have been exhaustively examined.

A source registry is retained at `research/dresden/sources.json`. It distinguishes the overview from research authorities and from facsimile access. A future transcription must preserve visible numeral marks, inferred numeric values and scholarly interpretations as separate fields. A reconstruction cannot turn an unreadable image into an observed numeral simply because its preferred arithmetic is attractive.

## Long Count as exact integer arithmetic

Digits are most-significant first. The positional weights from the right are 1, 20, 360, 7,200, 144,000 and further factors of 20. Consequently, the second-lowest digit has radix 18 rather than 20. `long_count_days` rejects noncanonical lower digits and negative values, while permitting an unbounded leading digit. `days_long_count` can use one through 64 places, retaining an unbounded leading place; the two operations are exact inverses on nonnegative integer days within their declared representation.

For example, 4.12.8.0 means 4·7,200 + 12·360 + 8·20 = 33,280 days. Treating the string as ordinary base 20 would give the wrong result. Leading zeroes may be supplied when canonical; a Gregorian correlation is never inserted implicitly. Signed elapsed differences are ordinary integer differences between nonnegative encoded dates.

## Calendar Round and noncoprime compatibility

The default arithmetic epoch convention is 4 Ajaw 8 Kumk'u, encoded by number 4, day-sign index 19 and Haab day 348. Indices run from 0 to 19 for the day signs, with Imix at 0 and Ajaw at 19. Haab is supplied as a linear day index 0 through 364; the month-name layer is not implemented. These conventions are replaceable through the `origin` argument.

A requested number, sign and Haab position becomes three simultaneous congruences modulo 13, 20 and 365 relative to that origin. The first two define a unique class modulo 260. The Haab condition is compatible precisely when it agrees modulo gcd(260,365)=5. A compatible Calendar Round therefore identifies a class modulo lcm(260,365)=18,980. The test suite roundtrips every one of these 18,980 day positions.

For general progressions d≡a (mod m) and d≡b (mod n), let g=gcd(m,n). A solution exists if and only if g divides b−a: necessity follows by subtracting the equations; sufficiency follows by solving (m/g)k≡(b−a)/g modulo n/g, where m/g is invertible. The returned progression has period mn/g. The implementation handles signed days, modulus one, incompatible phases and arbitrary positive integer moduli without expanding a residue table.

In a closed interval [L,H], the count is floor((H−a)/m)−floor((L−1−a)/m), with zero returned for reversed endpoints. The first day is L+(a−L mod m); rank r selects this day plus rm whenever r lies in the exact count. The corpus counts 10^30+1 joint-cycle dates over [0,37,960·10^30]. Storage is independent of that population size.

## A direct bridge to polynomial machinery

`polynomial_calendar` accepts an original-day Boolean polynomial sign predicate and a calendar progression d=a+mk. It substitutes a+mk into every polynomial before invoking PerfectPower's exact integer polynomial-domain engine. The accepted k intervals are clipped to ceil((L−a)/m) through floor((H−a)/m), counted, and transported back to days. `polynomial_calendar_select` recovers the original day for a rank.

This matters when the date constraints are combined with polynomial inequalities from a declared approximate model, uncertainty envelope or bounded research hypothesis. It also avoids constructing a residue truth table of length m. Even a modulus of 10^30 can be processed by a small parameter polynomial. Completeness is relative to the supplied polynomial model: a polynomial approximation to an astronomical observable still needs independently justified approximation bounds.

The retained synthetic window (d−1,000,000)²≤50,000² intersects the example Calendar Round in exactly five dates: 965,780, 984,760, 1,003,740, 1,022,720 and 1,041,700. It is a declared polynomial window, not a historical uncertainty estimate.

The focused regression compares transported populations against exhaustive original-day evaluation and includes a huge-modulus case. Existing Sturm certificates remain Python replay objects. The new Lean module proves the mathematical source-predicate and coordinate bridge; it does not verify the Python or JavaScript producer or general Sturm completeness.

## Venus: a sourced arithmetic reproduction

The corpus selectively recomputes correction arithmetic discussed in Gerardo Aldana's 2016 paper, *Discovering Discovery: Chich'en Itza, the Dresden Codex Venus Table and 10th Century Mayan Astronomical Innovation*, especially printed pages 65–69. The registry links the openly accessible paper. Its historical reading is attributed to that author rather than asserted as the sole interpretation.

The canonical arithmetic uses 584 days per round and a 37,960-day Great Cycle. Five rounds equal eight 365-day years: 5·584=8·365=2,920. Sixty-five rounds give 37,960, a multiple of both 260 and 365. The recorded correction-interval values used here are 33,280, 68,900, 185,120 and 9,100. With correction factor 2,340, their integer representations are respectively (x,y)=(1,2),(2,3),(5,2),(4,61) in x·37,960−y·2,340. Each identity is recomputed.

The first two corrected spans become 71,240 and 106,860 days after adding one Great Cycle. Their ratios to two and three Great Cycles agree at 137/146. Dividing by their respective 122 and 183 Venus rounds gives the same exact mean, 35,620/61 days. Transporting the supplied base date 9.9.9.16.0 yields 9.19.7.14.0 and 10.4.6.13.0 respectively, reproducing the relevant Long Count arithmetic.

An apparent source typo is retained explicitly in the receipt. For the third correction interval, the printed decimal expression uses 3·37,960−2·2,340, which evaluates to 109,200 rather than 185,120. The preceding Long Count expression uses coefficient 5, which is consistent with 185,120. The receipt preserves the printed discrepancy and the independently computed consistent coefficient; it does not silently rewrite the source.

## Executable correction hypotheses and complete error envelopes

`VenusRule` declares a block of R rounds taking D days. For round n=qR+r, with 0≤r<R, the execution day is anchor+qD+584r. Repeating this rule indefinitely is an explicit computational experiment; it is not inferred to be the author's complete historical protocol. The uncorrected 584-day rule is labelled synthetic, and the two sourced correction blocks are labelled literature interpretations.

Against a supplied positive rational constant mean P, the elapsed error is q(D−RP)+r(584−P). The default reference is the decimal mean 583.9214, represented exactly as a rational. This measures drift against a mean model, not heliacal visibility, conjunction time or an ephemeris. Correlation constants, observer location, atmosphere and the variable physical synodic interval remain external inputs.

There is no need to enumerate a long run. Error is affine in q and r over every full block. Its extrema occur at the corners of the rectangle of completed blocks, or at the endpoints of the final partial block. `error_envelope` evaluates at most six candidate rounds, including the first and last full-block boundaries and the final round. The corpus executes a horizon of 10^12 rounds. Tests compare the envelope against exhaustive execution at horizons around both correction boundaries and for reference means below, equal to and above 584.

## Reconstruction and identifiability

`reconstruct_intervals` takes a finite set of nonnegative integer candidates at each labelled slot and an exact target sum. It builds prefix sum populations by dynamic programming. The weight at a sum counts all assignments reaching it. A backward pass retains precisely those values at each slot participating in at least one complete assignment. A witness is returned when one exists; uniqueness means the assignment count is exactly one. Duplicate numeric values in a slot count as one candidate value, not distinct palaeographic readings. Distinct reading identities belong in the alternative-reading layer.

The forward recurrence is C_(i+1)(s)=sum over v in A_i of C_i(s−v), starting at C_0(0)=1. Induction proves that its weights count all assignments. Backward reachability intersects prefix support with the suffix requirement, so a retained value has a full completion and every full completion is retained. Nonnegative choices justify pruning totals above a nonnegative target. A negative target produces an empty population. Explicit work budgets raise an error before any complete result is returned when exceeded.

The proposed standard eclipse span is 11,960 days over 405 lunations, yielding 46 ritual cycles and mean 2,392/81 days. The surviving published table instead ends at 11,959 days; the source audit below keeps that distinction explicit. To demonstrate identifiability, the corpus separately declares a synthetic vocabulary of 69 labelled slots, each allowed 148, 177 or 178 days, summing to 11,960. This admits exactly 3,048,179,358,545,703,294,215,589,000 assignments. It establishes that a total and interval vocabulary alone cannot determine an ordering. It does not establish that any of those assignments is a historical table.

## Exact overlapping restarts and bounded drift policy

The restart engine places the 55 intended station months at every base generated by a declared repeating restart pattern. For four 358-month steps and one 223-month step, the base pattern has period 1,655 months. Overlapping table predictions are deduplicated by residue, while each residue's earliest activation is retained. This gives 227 eventual prediction residues and density 227/1,655. The startup boundary remains exact: a residue contributes only after its first occurrence. Existing semilinear counting and selection operate on this domain, including ranks of 10^30. These are predicted lunation indices, not a count of physically visible eclipses.

Figure 8 supplies rounded mean offsets of +0.0972 days per 358-month restart and −0.42356 days per 223-month restart. The terminal offset for their five-step combination is −0.03476 days regardless of ordering. Under precisely these supplied offsets, a bounded minimax dynamic program checks all orderings and returns the unique sequence 358, 358, 223, 358, 358. Its maximum absolute prefix offset is exactly 5,729/25,000, or 0.22916 days. This is a mathematical optimization under rounded mean offsets; it does not establish that an ancient practitioner selected that order.

The first dynamic-programming pass minimizes the maximum prefix magnitude at each lattice state. A second pass counts every path staying within the final global bound; retaining only prefix-minimal predecessors could incorrectly discard paths that still attain that final bound. Enumeration tests check both the optimum and the number of attaining paths. The separate mean-period drift function uses caller-supplied rational lunar and nodal means; its outputs are not silently identified with the differently rounded figure offsets.

## Kernel-checked polynomial calendar models

The new `PerfectPower/DresdenCalendar.lean` compiles against the pinned Lean and Mathlib 4.20.0 environment. No sorry, custom axiom or native reduction axiom is accepted. `make dresden-lean` recompiles the four imported PerfectPower dependencies sequentially, compiles the new module, and checks its audit.

A polynomial condition includes all six comparisons with zero, conjunction, disjunction and negation. Lean proves that replacing every polynomial P(d) by P(a+mk) preserves the condition at every rational k. For integer days and a positive canonical progression period, the accepted bounded day set is exactly the injective affine image of the accepted bounded parameter set. Thus finite cardinality and zero-based rank are preserved, including negative bounds in the mathematical theorem. A checked parameter member at a stated rank yields an original day satisfying the source condition and a unique original-day selection at that rank. The finite-set interpretation is a mathematical specification, not an instruction to enumerate enormous intervals.

Canonical Long Count encodings retain the nondecimal eighteen-uinal carry and have unique five-place digit tuples. Restart tails with the same residue unite at the earliest activation boundary.
