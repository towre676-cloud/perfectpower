# PerfectPower formula transport: first parallel checkpoint

This checkpoint connects arithmetic solution theorems to predicates surrounding the original equation. It adds a reusable Lean interface, a narrow SMT-to-Lean emitter, a compiled independently authored example, and a consumer of an existing complete Mordell theorem. It changes no number-theory sources and no existing SMT adapter behavior.

For a relation R with a complete finite list L, `finite_relation` proves that R(x,y) and C(x,y) is equivalent to membership in L together with the original residual predicate at the selected point. `finite_exists` eliminates the arithmetic variables entirely: existence of x,y satisfying both predicates is equivalent to existence of a point p in L satisfying C(p). Additional program variables can be captured by C. The theorem does not assume that C is linear, decidable, or arithmetic.

The singular curve x²=y³ has infinitely many integer points. `square_eq_cube` proves its exact parametrization x=t³, y=t² for all integers t, including negative t and zero. The proof uses the coprime-power theorem over the rationals. A rational parameter with an integral cube has denominator one, so the parameter is integral. The context and existence theorems compose this result with any predicate C. This is a solution-set transformation; it does not promise that the resulting problem is computationally easier.

The external pilot is the repository's byte-pinned cvc5 regression `disj-eval.smt2`. It restricts x to {5,7,9,27,10}, y to {0,1,9,8}, and asserts x²=y³. The emitted Lean theorem states equivalence of the full existential query to the residual constraints at (t³,t²). The emitter accepts two plain integer constant names, one direct square/cube assertion, integer arithmetic using addition, subtraction and multiplication, Boolean combinations, comparisons, and one query. It rejects division, remainder, other sorts, scopes, additional variables, and unsupported commands. The source SHA256 appears in the generated file. Source parsing and translation remain Python code; Lean checks the emitted mathematical statement, not the correctness of the parser or the meaning of the source hash.

The finite pilot imports the existing unconditional `K2.plus2` theorem. `plus2_consumer` proves that an arbitrary constraint C admits an integer point on y²=x³+2 exactly when C(-1,-1) or C(-1,1). This uses the complete point theorem, not bounded search or a named analytic premise.

Validation consists of focused Python tests for retained residuals, reversed equality and unsupported inputs, compilation of the new Lean module, and compilation and axiom inspection of both consumer theorems. The independent pilot is additionally solved in its original and parametrized forms with Z3 5.1.0; both return SAT, with (x,y)=(27,9) and t=3 respectively. The recorded single-run times are illustrative only: the original regression is easy, and this is not evidence of an industrial speedup. No whole-repository release check or downstream SMT-proof integration is claimed.

Run `PYTHONPATH=python python -m unittest python/tests/test_formula_transport.py` and `python parallel_formula/check.py` from the repository root. The latter regenerates the theorem from the committed external source and checks the required Lean modules and consumer files. The next extension is a source-bound proof generator for affine Mordell substitutions, followed by bounded Pell consumers. Broader normalization and proof caching should carry integer lattice restrictions explicitly.

## Second checkpoint: affine integer images and finite formula compilation

The upstream branch now contains the other session's complete quartic example and foundational weighted-orbit work. Its k=22 slab pilot checks only the first small chunk; no full k=22 curve theorem has been promoted. This consumer checkpoint uses the complete results and preserves that distinction.

`FormulaAffine.affine_pair_finite_exists` treats disguises of both coordinates. If R has complete list L, then existence of n,m with R(rn+s,am+b) and C(n,m) is equivalent to existence of (X,Y) in L with r dividing X-s, a dividing Y-b, and C((X-s)/r,(Y-b)/a). Both scales must be nonzero. The two divisibility conditions are essential: points in the target curve outside the integer image are excluded before any residual predicate is evaluated. Negative scales are covered by the same theorem. This is a reusable coordinate-transport theorem, not a new Diophantine classification.

`python/perfectpower/finite_formula.py` recognizes expanded affine squares against affine cubes, and the complete quartic v²=3u⁴+3u²+1. It reads 72 positive-k complete-list statements from the current source tree; a generated use of a theorem must still compile before acceptance. Negative k=-1 is also supported. The generator emits an exact polynomial-identity proof for the original selected equality, an existence equivalence retaining every supported residual assertion, and a finite disjunction in SMT-LIB. Extra integer variables become parameters in the first theorem and are existentially quantified in a second whole-query theorem. Each generated namespace is bound to its source hash so several outputs can coexist. The parser and SMT serializer are Python code; a source hash is a binding annotation, not a formal proof of SMT parsing. A downstream SMT checker does not yet accept this Lean proof as an SMT certificate.

Six authored fixtures exercise a shifted square and cube with an extra variable, an empty affine image, a negative cube scale, the existing k=5 theorem, the new quartic theorem, and cancellation of an extra variable inside the selected equality. Every emitted Lean equivalence compiles with only propext, Classical.choice and Quot.sound. The focused suites run 26 tests, including 300 randomized affine images compared with exact bounded integer evaluation and residual SMT comparisons under 405 assignments. These checks do not constitute a full repository build. The generator can emit for all 72 available positive-k statements, but this checkpoint compiles concrete consumer proofs for k=2 and k=5, k=-1, and the quartic; it does not claim compilation of 72 consumer files.

Z3 5.1.0 was run with a two-second budget on the authored fixtures. Three original queries returned unknown while their finite replacements returned unsat in approximately one millisecond. The remaining original queries returned unsat once and sat twice, agreeing with their replacements. These are useful mechanics demonstrations, not independently sourced industrial performance evidence. Exact timings and models are in `finite_results.json`. The quartic and k=5 positive-argument examples show how a complete point theorem can remove search from an unsatisfiable residual problem. The extra-variable example demonstrates that couplings survive the replacement rather than being dropped.

Run `python parallel_formula/check_finite.py` to regenerate the proof files and reduced SMT inputs, build the necessary source theorem modules, and compile every proof fixture. Run `python parallel_formula/bench_finite.py` with z3-solver installed to reproduce the original/reduced solver comparison. To emit a new source, use `PYTHONPATH=python python -m perfectpower.finite_formula input.smt2 --output result.lean --smt-output reduced.smt2`, then compile result.lean before consuming its replacement. Scripts with scopes, unsupported arithmetic, noninteger sorts, unsupported Boolean syntax or unfinished curve families are rejected.
