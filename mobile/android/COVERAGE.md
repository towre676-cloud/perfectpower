# PerfectPower Explorer for Android

This Android edition carries the complete repository snapshot used by the desktop release. A per-file SHA-256 manifest and an archive checksum verify the package. First launch checks every original source and data file before the interface opens. Bundling a proof source is not a claim that Android has compiled the proof.

The original 145 command families and their nested operations remain discoverable through forms generated from the repository's real argument definitions. The mobile edition retains the mathematical laboratory, command workbenches, edited JSON inputs, file search, original-file export, visual library, proof and evidence browser, saved runs, replay, generated-file export, dark appearance and reduced motion. Touch rotation and pinch zoom use the same local Three.js scenes. A complete navigation menu exposes every workspace.

Python 3.10 runs on the phone. NumPy 1.23.3, SciPy 1.8.1, SymPy 1.14.0 and mpmath 1.3.0 are bundled. This Android SciPy build is older than the repository’s declared ≥1.9 numerical extra: compatibility checks and representative numerical paths are tested, but newer SciPy APIs are not guaranteed. The mobile host maps NumPy’s newer trapezoid spelling to the same trapz algorithm. The exact allocation planner and unweighted CNF counter are compiled from the retained C++ sources for ARM64 and x86-64, with source and binary digests. Native execution is not a Lean kernel proof. Results preserve each engine's mathematical scope.

Each computation uses an Android service in a separate process. A cancel or deadline terminates that process. The interface and saved files remain available. Runs are serialized to keep engine-global state and memory use separate. Android may stop computations when the app is backgrounded or under memory pressure; interrupted runs are identified and can be replayed. Long computations are best run with the app visible. A partial or interrupted output is never presented as a completed answer.

Complete content does not imply every research dependency can execute on Android. Lean, Lake, PARI/GP, Sage, Why3, BLAST+, external compilers, OR-Tools, python-flint and Z3 are not bundled. Operations that require them retain their source, forms, example inputs and historical receipts, and report the missing dependency instead of substituting a sample result. Pure Python operation paths remain available. Network adapters and retained pages with external CDN links need an internet connection. Historical HTML is kept intact; its own desktop-oriented layout may need zooming on a phone. The Dresden web source is included as source rather than a separately compiled Android application.

Windows Electron executables and the Windows installer runtime are replaced by the Android application runtime. Every tracked repository file, including the source and provenance of the desktop application, is retained. Repository DLLs and Linux libraries are preserved as original files; the Android native libraries are additional assets.

Android system file picking exports original repository files, complete run JSON, stdout, stderr and generated artifacts without broad storage permission. UI previews cap large arrays and text for memory use; exported files contain the full saved output. Exports use the local authenticated server. No credentials or JavaScript-to-native bridge are exposed to repository HTML.

The APK is signed for direct installation and is not a Play Store release. Minimum Android version is 13; the bundled scientific wheels target devices using 4 KB memory pages, including the Galaxy S21. Devices with 16 KB memory pages have not been validated. Supported architecture is ARM64 for phones, including the Samsung Galaxy S21, plus x86-64 for testing. Detailed package and engine checks accompany the release. A real-device GPU and touch test must be distinguished from build and emulator checks.
